## ITEM 7 / Q5 — DOES THREAD 152 BLOCK? Answered from the FUNCTION.
==============================================================================
A projection needs a CURRENCY check: something must prove the emitted block
still matches the source it was derived from. The only body<->register
comparison in the system is cycle_check._compute_coherence. Its source:

    def _compute_coherence(parsed, plan_path):
        """Compute the coherence field value for --emit-manifest."""
        ref = parsed.get("walk_register_ref")
        if not ref:
            return "N/A (no register declared)"
        git_root = _find_git_root(plan_path)
        if not git_root:
            return "N/A"
        reg_path = git_root / ref
        if not reg_path.exists():
            return "N/A"
        walk_data = parsed.get("walk_data", {})
        total_walks = max(walk_data.keys()) if walk_data else 0
        if total_walks == 0:
            return "N/A"
        try:
            reg_text = reg_path.read_text(encoding="utf-8")
            walks_with_rows = 0
            for wn in range(1, total_walks + 1):
                if re.search(rf"\b[Ww]alk\s+{wn}\b|\bw{wn}\b", reg_text):
                    walks_with_rows += 1
            return f"{walks_with_rows}/{total_walks} walks have register rows"
        except Exception:
            return "N/A"

THREE DEFECTS, each disqualifying for a currency check:
  1. `if total_walks == 0: return "N/A"` — it is DISABLED by exactly the

     wNN token. Gate-2 week names (gate2-pt-w28-a, forge-cycle-w29) score as
     walks; no cycle in the corpus ran 20 walks.
  3. it runs ONLY under --emit-manifest — once, at freeze. A projection
     drifts DURING a cycle; a check that runs at the end cannot catch it.

⛔ ANSWER: NO CURRENT CHECK CAN VERIFY A PROJECTION IS CURRENT.
