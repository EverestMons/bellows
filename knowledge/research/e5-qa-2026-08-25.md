### Hook half LIVE AT MERGE

The keyed predicate activates the moment the merged code is checked out. The next `/wrap` on this machine runs the keyed stop-hook arm. On first wrap post-merge, the newest `Lessons-swept:` line in the baton will be historical-format (no `[sid:]` token) — the stop-hook keyed arm will FAIL 3b with the actionable message: "The newest Lessons-swept: line has no session-id key (historical format). Do the 3b transferable-lessons sweep..." This is the check WORKING: the failure message IS the operator's instruction. The wrap writes its own keyed `[sid: <prefix-8>]` line, and re-check passes.

**First-wrap walkthrough:**
1. Operator runs `/wrap` on this machine after merge
2. Stop hook fires `wrap_check.py <session-id> stop`
3. `_find_newest_sweep_line` finds the most recent `Lessons-swept:` line — no `[sid:]` token
4. `_extract_sid` returns `None` → historical-format FAIL with the actionable message
5. Operator performs the 3b sweep and adds `Lessons-swept: <today> [sid: <prefix-8>] — <delta>`
6. Re-check: `_find_newest_sweep_line` finds the new keyed line → `_extract_sid` returns the prefix → `session_id.startswith(token) and len(token) >= 8` → PASS

**The daemon is NOT involved.** This is a pure hook-side change; no bellows restart needed.

### Mixed-window invariant (S3-3)

Hooks and check ship from one checkout in one commit. An OLD debt hook against a NEW check would default `caller="stop"` (since the old hook passes no argv[2]) and false-inject the keyed arm at every session start — the debt hook would FAIL 3b on sid mismatch for any session that isn't the baton's newest. The single-commit shipping is the guard: both hooks and wrap_check.py update atomically in one `git pull`.
