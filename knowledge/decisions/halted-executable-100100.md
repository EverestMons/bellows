## Why this exists

Two standing rules meet at every deposit with no tool between them (thread 329). ## What this does NOT do

- It does not change the depositor or its admission: the daemon's path is untouched, and the tool calls the same two methods.
- It does not edit bellows `CLAUDE.md` — step 2's pointer to the tool is the CEO's Post-close apply act.
- It does not decide a deposit: it prints what the depositor would assign; the depositor's own admission at `ready-` still decides.
- It does not open, create or write any database, and runs no daemon, claim or gate.
- It does not catch every mis-parse: a skipped stanza line and a fallback are reported; a value the parser reads wrongly — a comma inside one path — is not.
