## What this changes

⛔ **One resolver, one rule, one pass-through.**

1. **`_resolve_write(path, project_root) -> (repo | None | UNKNOWN, rel)`** — every write path becomes *the repo it lands in* plus the path inside it. **Identity comes from the RESOLVERS, never from a checkout's name** (E6). Let G = `bellows_root.resolve_governance_root().resolve()` and P = `bellows_root.resolve_projects_parent().resolve()`; an absolute path is `Path(p).resolve()`d first (symlinks and `..` collapse, E9). **Mini shape (G ≠ P):** under G → governance (token `eluvian-governance` whatever the directory is called), `rel` relative to G; else under P → first segment = repo, rest = `rel` — a SINGLE-segment path under P (a file directly in the projects parent) names no repo and is UNKNOWN (f9); else UNKNOWN. **Shop shape (G == P — the Air, MACHINE_SETUP §1, `bellows_root.py:55`; ruled 2026-09-08, C1):** under G, a path is governance iff its `rel` has ONE segment (a root file, f3) or its first segment is `governance` (the lane's own subtree, which the daemon derives as `<G>/governance`, `depositor.py:122`); every other first segment is that project's checkout; else UNKNOWN. An absolute path under NEITHER root is an UNKNOWN repo on both shapes (E1 — fail-shut, ruled 2026-09-08: a path this shop cannot place never auto-clears). `~/` and `../` are out of tree. A relative path is normalised with `os.path.normpath` (`./x` → `x`; backslashes are NOT translated) and belongs to the filing project — whose identity is ALSO by resolver: a `project_root` whose resolved path equals G or lies under `<G>/governance` is governance (E7, C1 — never merely 'under G', which on the shop shape is every project; the daemon derives the governance lane's root as `<G>/governance`) — EXCEPT a leading segment that names an infra project when the path does not exist under the project (`bellows/depositor.py` spelled from the parent), and EXCEPT any relative path, bare or not (E5), that does not exist under the project but does exist under the governance root (a bare `DRAFTING_CYCLE.md` or `governance/GUARDRAILS.md` filed from tuyere — thread 66's hole). The literal `<declare>` is an UNKNOWN repo in every context (E8). `project_root == ""` (no context) makes NO filesystem check: a leading segment that names an infra project is that repo; anything else is UNKNOWN (f1) — and this rule is evaluated FIRST, before the absolute arm, so an absolute path with root `""` is UNKNOWN unless its leading segment (after `lstrip("/")`) names an infra project (C4).
2. **`_SHOP_INFRA_PROJECTS`** — a static floor `{bellows, forge, forge_lessons, lessons-forge, anvil, eluvian-governance}` ∪ `config["shop_infra_projects"]` (extension only, never a disable — Ruling 119; the shape `plan_lint.KNOWN_PROJECTS` already uses: a static floor ∪ `config.json`, f5).
