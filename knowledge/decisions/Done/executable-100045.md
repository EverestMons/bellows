## What this changes

⛔ **Five gate arms, each read against the failure that measured it. Three gate NAMES enter the request table as `_KNOWN_GATES` rows — the two new gates and `qa_test_result`, rowless until now (f2, E4); failures keep the existing `{"gate": …, "evidence": …}` shape and the override path.**

1. **`_gate_scope_check` — a declared Scope is authoritative (191).** When the union of the steps' `**Scope:**` blocks declares anything (files or `dir/` prefixes), a changed file passes ONLY by a DECLARED path: a Scope entry, a Scope `dir/` prefix, or an entry of the step's `**Deposits:**` block (plan-authored and machine-parsed — a declaration, not prose; the block and inline forms only, never the `Deposit … to X` prose fallback; an entry ending `/` is a prefix). Declared entries are NORMALIZED before matching: an absolute entry under the project root becomes project-relative (the tuyere habit `/Users/…/tuyere/tuyere/claims.py`, P14); an absolute entry outside the project root matches nothing. A changed path (always project-relative — the daemon diffs `--relative`) matches a declared file when equal, or when the declared path carries exactly ONE extra leading segment (`d.split("/", 1)[1] == fpath` — the corpus habit `bellows/knowledge/…` beside `knowledge/…`, P13); a declared prefix matches when `fpath.startswith(p)` or, with one extra leading segment, `fpath.startswith(p.split("/", 1)[1])` (PT Rule 26's own spelling `bellows/knowledge/qa/evidence/<slug>/`). Nothing floats further: a declared `tests/fixtures/x.py` does not clear `x.py`, a declared root `gates.py` does not clear `tests/fixtures/gates.py`. The two prose arms — *the path or its basename appears anywhere in the step text* and *an ancestor directory is mentioned* — apply ONLY when no Scope block is declared (legacy plans; the `PLAN_TEXT` fixture in `tests/test_gates.py` is one). The `basename in declared_files` arm is deleted — the one-segment tolerance replaces it. Lifecycle-file allowlists are untouched.
2. **`_gate_qa_test_result` — the suite log is chosen by CONTENT (43).** Among the step's `.txt` deposits (plan-declared, else agent-declared), the evidence file is the first, in Deposits order, whose text matches the gate's OWN `_PYTEST_SUMMARY_RE` (the borderless counts line, canary 441 — ONE reader, no second regex); when several do, a basename containing `suite` wins; when none does, the gate FAILS naming every `.txt` it inspected. The `full-suite`-in-basename preference survives only as that tie-breaker.
3. **`_gate_quoted_test_nodes_exist` — NEW, QA steps only (65).** Every `tests/<path>.py::Name[::Name…]` token in the QA `.md` deposits must name a file that exists in the worktree and a final segment (parameter brackets stripped) defined there as `def Name` or `class Name`; the gate FAILS listing every node it could not find. A confident NON-EXISTENT identifier stops being indistinguishable from a right one (a real-but-wrong one is fork 6). Only the `tests/…py::Name` form is read — a bare `test_x.py::name` is not (every one of the 192 corpus ids carries `tests/`, P7). The deposit is read RAW — fenced pytest output included (`strip_fenced_code_blocks` applies to plan text, not deposits); a node pytest itself printed exists by construction.
4. **`_gate_rule_22_verification` (d) — the LESSONS status marker is not a hedge (136).** The exact form `\[?status:\s*pending\]?` is stripped from a positive-status row before `_hedging_in_status_vicinity` runs; the bare word stays a hedge. (d) is cell-scoped — it fires only on a keyword IN the status-bearing cell — so the mirror is narrow by construction. Mirrors the agent-side block amended at governance `34a95253`.
5. **`_gate_mutation_result` — NEW (192).** For every `knowledge/mutants/*.run.txt` among the step's deposits (plan-declared, else agent-declared): resolve it, and require its last `MUTATION:` line to read `N killed, 0 survived, 0 error` with N ≥ 1 — else FAIL quoting the line (or its absence). A step that declares neither is untouched.
