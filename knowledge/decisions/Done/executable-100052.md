## What this does NOT do

- ⛔ **It does not change how QA runs pytest** — `-q` stays; 203's asymmetric rule is built for `-q` output and tightens by itself on verbose output.
- ⛔ **It does not exempt any quoted id** — a placeholder written as `tests/path.py::Node` or a node quoted from ANOTHER project's evidence fails the node gate (P3). The escape is the author's: write placeholders with angle brackets (`tests/<file>.py::<Node>` does not match) and foreign or undefined ids by METHOD NAME or with the `tests/` prefix elided (`…::test_x` does not match). Fork 1 if the class recurs on a LIVE receipt (the corpus replay naming shipped receipts is not that).
- **It does not strip fenced code blocks before reading nodes** — 203 reads pytest output the receipt pastes in fences.
- **It does not re-gate any shipped artifact** — the gates run at the next pause of the next plan. ⚠️ From then on a DEV dev-log that quotes a node the step renamed or deleted (a stale id in its failing-first paste) fails the node gate at that step's pause; the DEV corrects the dev-log — a record defect, found where it is made.
- **It does not add a gate for a dev-log's PROSE** — only declared headings and declared verbatim cells are compared; an undeclared section is the author's. A receipt line whose node NAME contains `passed` or `ERROR` is unclassifiable and silently skipped by 203 (latent, E15).
- **It touches `plan_lint` at ONE string** — check (u)'s rationale (change 8); the `**Headings:**` and `**Verbatim:**` lines are optional and `plan_lint` does not read them; a plan without them declares nothing.
- **It does not repair `tools/passfail_record_census.py`'s stale gate list** (fork 4).
