1. **`_main_branch(project_path, slug=None) -> str`** — the detection `_teardown_worktree` does inline today (`symbolic-ref --short refs/remotes/origin/HEAD`, strip `origin/`, fallback `main` with the existing WARN carrying `slug`), lifted into a helper the teardown, `_checkout_is_current` and `_push_main` all call.
2. **`_checkout_is_current(project_path, slug=None, fetch_timeout=30) -> (ok: bool, detail: str)`** — FIRST the daemon's own in-place sentinel: `not os.path.exists(os.path.join(project_path, ".git"))` → `(True, "not a git repo — in-place")`, never a network call (E9/C12: `git rev-parse --git-dir` would find a PARENT repo); then `b = _main_branch(project_path, slug)`; `git rev-parse --abbrev-ref HEAD` must equal `b`, else `(False, "stale checkout: HEAD is on <x>, not <b>")` (E10: the merge lands on HEAD); then `git fetch origin <b>` (timeout `fetch_timeout` s, 30 by default) — a non-zero exit, `TimeoutExpired` or `OSError` → `(False, "fetch failed: <first non-empty stderr line>")` (fail-closed, C10/C6); then `git rev-list --count <b>..origin/<b>` (behind) and `origin/<b>..<b>` (ahead); `(True, "current")` only when both are 0, else `(False, "stale checkout: <b> is <behind> behind / <ahead> ahead of origin/<b> — pull (behind) or push (ahead) on this checkout; the hold releases itself on the next poll that finds it current")`. A fetch updates `refs/remotes/origin/*` only.
3. **Wire point A — the claim path, BEFORE `plan_claim.claim_gate`** (`bellows.py` claim flow, after the clearance re-check at `:994-1000` and before `:1001` — C1/E1: `claim_gate` in `advisory`/`required` mode takes the tuyere slug claim, and a refusal after it would strand the slug with no release path): `ok, detail = _checkout_is_current(project_path, slug)`; if not ok → write the daemon's existing auto-hold shape (the inline arm at `:2435-2440` / `:2471-2476`): `hold-<filename>` beside a `.hold.json` `{"hold_reason": "stale-checkout", "detail": <detail>, "held_at": <iso>}` (sidecar first, then the rename — the existing arm's order; a crash between them leaves a claimable file the next poll re-holds), rename the bare file to `hold-<filename>`, `_log("WARN", f"⚠️ HOLD — {detail}", slug=…)` ONCE, `bellows._seen.discard(verdict.slug_from_path(plan_path))` (the exact spelling at `:1003-1005`), return. 4. **Wire point A′ — self-release in the rescan** (`Orchestrator._rescan(handler)`, `bellows.py:2732`, as its first arm — the method the main loop runs every 30 s and the tests call directly): for every `hold-*.hold.json` in a watched lane (`config["watched_projects"]`, `:2750`; the lane's project is `Path(decisions_path).parents[1]` — the claim path's own derivation at `:898`) whose `hold_reason == "stale-checkout"`, run `_checkout_is_current(project_path, slug, fetch_timeout=10)`; re-checked with `fetch_timeout=10` and AT MOST ONE held plan per rescan (oldest `held_at` first — the loop stalls ≤ 10 s per pass, never per plan); when `(True, …)` → rename `hold-<name>` back to `<name>` (⛔ only when no bare `<name>` exists in the lane — a re-deposit under the same name leaves the pair in place with a WARN, never an overwrite), THEN remove the sidecar, `_log("EVENT", "stale-checkout hold released — checkout current", …)`; the claim path then proceeds on this or the next poll. A `stale-checkout` hold is never released by `clear_plan` — it has no clearance semantics; a human who pulls or pushes releases it by making the checkout current.
5. **`_push_main(project_path, branch) -> (ok: bool, detail: str)`** — `git push origin <branch>` (timeout 60 s); `(True, (stdout + stderr).strip())` on exit 0 (E12: git writes push progress to stderr), else `(False, <first non-empty stderr line, then the rest>)`; `TimeoutExpired`/`OSError` → `(False, "push failed: …")`. Never `--force`, never a rebase.
6. **Wire point B — the merge path** (`_teardown_worktree`, immediately after step (c)'s merge succeeds and BEFORE (d) removes the worktree): `ok, detail = _push_main(project_path, main_branch)`; if not ok → `raise WorktreeTeardownError(f"worktree_teardown_push_rejected: push of {main_branch} rejected after merging {branch_name} for slug {slug}: {detail} — someone landed on origin/{main_branch} outside a plan; on this checkout: git fetch origin && git merge origin/{main_branch} (resolve by hand), then re-issue continue — the retry merges (a no-op) and pushes again")`. The worktree and branch stay alive and `main` stays merged locally, as on a merge conflict today (P3).
7. **Wire point C — the continue-time retry** (`_retry_recoverable_teardown`, `bellows.py:2274-2276`): the allowlist predicate `all("worktree_teardown_dirty_tree" in evidence …)` becomes `all(any(m in evidence for m in ("worktree_teardown_dirty_tree", "worktree_teardown_push_rejected")) …)`, so a `continue` after the hand merge re-attempts the teardown: the merge is a no-op fast-forward, the push runs again, and on success the existing path records the landed shas (`record_commits`, C8) and clears the failure. Without this the Gap-1b guard rejects the continue and routes the plan to `halted-` (C2/E2). Nothing else in the retry moves.

## What this does NOT do

- ⛔ **It does not rebase, pull, or reset anything.** A stale checkout is held; a rejected push pauses; a human resolves; the daemon retries only what the human asked it to (`continue`).
- ⛔ **It does not push any repo but the project's own main branch**, never the governance root, the memory dir, or a worktree branch. ⚠️ **The push publishes whatever is on that branch**: with the claim-time equality, that is the plan's merged commits plus any commit a human made on that checkout DURING the run — the dirty-tree check (b) already surfaces uncommitted human work; a committed one rides the push. Stated, not guarded (f6).
- ⛔ **It does not change `plan_claim`** — cross-shop claim serialization is already its job — **and it does not turn on tuyere's `project_lock`** (project-level exclusivity across shops, the liveness half — thread 232, C7).
- **It does not push for in-place projects** — a project with no project-local `.git` runs without a worktree (`:1581`) and the teardown no-ops (`:2026`); the claim check uses the same sentinel and skips (test 11).
- **It does not retry a failed fetch or push on its own** (fork 1: a bounded retry with backoff, its own plan once the failure rate is measured); the continue-time retry runs only on the CEO's `continue`.
- **It does not move the wrap's push law** — the wrap still pushes; after this plan it finds nothing of the daemon's left to push.
