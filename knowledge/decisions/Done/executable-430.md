## Why this exists

Restarting Bellows fails with `another Bellows instance holds .bellows.lock — exiting` because the incumbent daemon (repro: PID 3969, started out-of-band via `nohup bellows.py`) is unreachable by `dashboard.py`'s restart, which only terminates its own `self.child`. diagnostic-429 mapped the machinery and specified the fix; this plan implements the **Full** scope the CEO chose (2026-08-15): a standalone stop path that reaches ANY incumbent regardless of how it was started, plus the self-diagnosing lock and the SIGTERM drain handler the kill path requires for safety. **Operational note (takes effect on next start):** shipping this fix does NOT retrofit the running PID 3969 — it has no drain handler and still holds the lock. The operator clears it with the NEW stop path (designed to work against a handler-less but idle incumbent), and the NEXT daemon start carries the self-diagnosing lock and the drain handler.

**Findings cited (Rule 27 — do not re-derive):** (Q3) the lock at `bellows.py:2472-2480` opens `"w"` and writes no PID; the error names no holder. (Q6 i) **NO SIGTERM handler exists anywhere in `bellows.py`** — the main loop (bellows.py:2416-2444) catches only `KeyboardInterrupt` (2442); an untrapped SIGTERM propagates as `SystemExit` and can kill the daemon mid-transition, re-tripping the 2026-05-24 state-divergence failures. (Q4/Q6 ii) `status.py` already has `get_daemon_pid` (lsof identity, `status.py:37-47`) and `probe_daemon` (flock liveness, `status.py:22-34`), and `query_in_flight` (`status.py:188-206`) for idle detection — all display-only today, wired to no stop path. (Q2) `dashboard.py` `_do_restart` (≈397) / `_terminate_child` (≈370-386) act only on `self.child`.
