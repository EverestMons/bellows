## CEO Context

The daemon keeps the code it loaded at start, by design, so every merged bellows plan reaches a machine only through a restart — and today the restart lives in the dashboard TUI on that machine's keyboard. Two things were true underneath that I measured this afternoon: `bellows.py` already carries a guarded `stop` and `restart` CLI (P1) — the lock holder found by `lsof`, an identity guard, an idle guard that refuses while a plan is running, SIGTERM then SIGKILL, and for `restart` a respawn — so the guarded path is code, not the TUI; and the respawn is a plain `Popen` in the caller's session, so a `restart` issued over ssh leaves a daemon that dies with the ssh session. The dashboard already tolerates a daemon it did not spawn (P3: it probes the lock, reads the pid by `lsof`, and delegates to `bellows.py stop` for a non-child incumbent). What is missing is a parent that survives logins and crashes and a restart verb that reaches it: a launchd agent, the same shape the tuyere watcher already uses on both machines (P2), with `KeepAlive` on unclean exit only so a guarded `stop` stays a stop, an `ExitTimeOut` longer than the daemon's 30-second drain, and a rendered PATH because launchd gives an agent none and the daemon's auth preflight calls `claude` by name (P4). With that, `bellows.py restart` becomes `kickstart` when the agent is loaded and a session-independent respawn when it is not, and the dashboard restarts through the same verb.

## Why this exists

The CEO's question of 2026-09-11 — must a bellows update mean a person at each keyboard — has "yes" as its answer today for one reason: the daemon's parent is a terminal. A launchd parent with a guarded restart verb makes the answer "no" for every machine on the tailnet, and gives thread 285 the parent its self-restart needs.

## What this does NOT do

- Install the agent on any machine (an operator act, Post-close; the QA verifies the render and the calls with `launchctl` shadowed).
- Restart at idle by itself (thread 285).
- Change the stop path's guards, or let `kickstart` bypass them: `bellows.py restart` still runs the guarded stop first; a bare `launchctl kickstart -k` is the operator's own act and lands on the daemon's SIGTERM handler, which drains.

## MUST-PRESERVE

- ⛔ **The guarded stop runs before every restart this plan issues** (`stop_daemon`'s holder, identity and idle guards, P1); `kickstart` is only ever called after it succeeds.
- ⛔ **`KeepAlive` on unclean exit only** — a clean `stop` stays stopped (t1, m3); `ExitTimeOut` exceeds the drain (t1, m4).
- ⛔ **The respawn without an agent is session-independent** (`start_new_session=True`, t4, m1).
- ⛔ **The dashboard never terminates a daemon it did not spawn** (t6).
- ⛔ **No machine state is changed by the plan's steps** — `launchctl` is shadowed in every test; the QA renders into `$T`.
- ⛔ **Every `expect_fail` is a class-qualified node id where the test is a method**; the mutation run is redirected into its deposit, never piped.
- ⛔ **The thread-262 stop** (PT v4.108 §8).
