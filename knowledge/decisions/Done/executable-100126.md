## CEO Context

At every SessionStart the debt hook runs `wrap_check.py <sid> debt` and injects the checklist when it exits non-zero. On that path the 3b arm asks whether any baton line reads `Lessons-swept:` with today's date. Yesterday's complete wrap carries yesterday's date, so the first session of every day reads as debt, and so does a session that runs past midnight: an overnight run was told at 02:35 that a wrap was incomplete.

The fix takes the arm off the debt path and nothing else. A new session's debt becomes the repo state a wrap leaves behind — uncommitted plans, verdicts, receipts, baton and memory, and unpushed commits — which the other arms already read. Those arms are the sync check, and they are correct as they stand.

**The lock is untouched.** `/wrap` still cannot end without this session's own sweep line, and a Stop that arrives without a session id keeps the date fallback. That is where capture is actually enforced, and it is work-scoped by construction: it asks the wrapping session about its own sweep, at the moment it wraps.

**What this gives up, stated plainly.** The debt path's only reminder about the lessons sweep goes. A session that commits and pushes everything but never runs `/wrap` is no longer flagged at the next session start. Measured over 2026-08-24 to 2026-09-17 (129 non-daemon session starts, P7): the date arm fired at 74 of them; a rule keyed on completed work would have fired at 39, of which only 8 were cases the date arm did not already catch. So the arm being removed was catching 8 real cases over 24 days at the price of 43 notices with no completed work behind them. Per-item capture (thread 411) is the instrument that would recover those 8 without the 43.

**A known gap, not closed here.** `/eluvian`'s alignment pass reads wrap debt by running the checker bare (`eluvian.md:24`), which takes the lock's sid-less path — so `/eluvian` keeps reporting every new day as debt after this plan lands. The CEO cut that edit from this plan on 2026-09-17 because it had not been surfaced to them, and opened **thread 409** to ask whether `/eluvian` should exist at all. This plan leaves it alone deliberately.
