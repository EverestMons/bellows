**What ships:** `_append_forward_row` currently reduces a whole `#### Forward Register` Receipt block to its FIRST non-empty line, so one block yields one row. Diagnostic 292 measured **11 of 19** historical blocks as multi-item — the reduction has been silently dropping content across the whole history, not merely in the current backlog. This plan makes the append bullet-aware:

```
If ≥2 non-empty stripped lines match ^(-\s|\d+\.\s), emit one row per matching line;
otherwise fall back to lines[0] (current behaviour).
```
