## CEO Context

When a Planner session is attending a plan, Bellows is meant to stay quiet rather than page you — the session already sees the pause. For verdict pages that has never happened: across the ten daemon logs, fifty verdict pages went out and not one was suppressed, because the page looks for the attending session under the plan's number while the deposit's receipt is filed under the plan's name. This plan hands the check the receipt's name, and makes the check count only the receipt that is exactly that plan's — a later deposit whose name extends it (`…-2`) no longer counts. After it, a verdict page for an attended plan stays silent; an unattended plan pages exactly as today, and a check that cannot run still pages. The failure, stale-checkout and startup-close refusal pages keep paging even when the plan is attended: measured, the attending session sees none of those events — the gate watcher it reads shows a verdict pause and a finished plan, nothing else — so staying silent there would leave nobody told; whether those pages should be plan-scoped at all is thread 354, yours. The halt pages and the startup close's close page page too, because the receipt is archived a few lines before each — thread 343. The class is shop-infra, so it holds for your release; after the merge, your restart makes it live.

## Why this exists

Thread 321 measured it and named the mechanism, and both re-derive at `65f713c` (P1, P2, P4). The ownership signal (#100054, the CEO's 2026-09-09 rulings) finds the attending session through the deposit's receipt, which `tools/deposit_receipt.py` names by the deposit's placeholder stem; the daemon's pages pass the plan's minted id — `run_plan` derives `plan_slug` from the claimed file's name after the rename to `in-progress-<type>-<id>.md` — so the glob `receipt-<id>-*.json` can never match, and every page of a claimed plan goes out. The prototype also showed the glob over-matching the other way: `receipt-<stem>-*` matches a later deposit's `receipt-<stem>-2-…`, whose session would then answer for this plan. The fix keeps the gate, its order and its key, and hands the check the one key a receipt carries.
