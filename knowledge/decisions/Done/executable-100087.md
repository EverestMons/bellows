## CEO Context

#100079 gave the dashboard a viewer mode: when the launchd agent is loaded, `_spawn_child` (dashboard.py:425–431) runs `launchctl kickstart -k gui/<uid>/com.eluvian.bellows-daemon` instead of spawning a child. The question it asks first — `bellows._agent_loaded()` (bellows.py:167) — is about the LABEL, which is one per user, while the check that led there — `status.probe_daemon(<root>/.bellows.lock)` at :503 — is about the ROOT the dashboard was started for. A dashboard on any other root (the PTY smoke test's `tmp_path`; a scratch clone; a second checkout) finds its own lock free, asks the global question, hears "yes", and kickstarts the one agent this user has — with `-k`, which replaces a RUNNING daemon and abandons its step at the 30-second drain (measured three times today, thread 297). The fix keeps every seam #100079 built and adds the missing fact: `launchctl print` names the agent's `working directory` (P2 — `/Users/marklehn/Developer/bellows` on the mini), so a helper can say whose agent it is; the dashboard kickstarts only when that directory IS its root, and a kickstart that follows a free lock or a guarded stop has no incumbent to replace, so it drops `-k`. A foreign root gets what it got before the agent existed: a child `bellows.py` under that root (the PTY test's mock). The hotfix's test-side guard stays, because a test that reaches launchd on a regression would kill the daemon again before the assertion could say so; the unit tests below are the proof that the branch is never taken.
