## CEO Context

Every draft closed today needed two runs of `close_cycle.py`, and one needed four. The cause is structural, not a flake. Step 3 emits the manifest while the draft's four keys still read `<declare>`, so the emitter's `cycle_check` token is computed on a manifest that cannot meet the close the new Closing line claims: `ESCALATE:claimed-close-unmet`. Step 4 splices the real values, and step 6's re-emit reads `BAR_MET`. The stored and live lines then differ in `cycle_check`, which #100069 deliberately refuses — its re-splice covers a `propagation_check` move only, and test c11 pins that a `cycle_check` drift fails. The second run passes because its first emit already sees the spliced values. The fix keeps c11's rule and removes the cause: when the manifest held placeholders at the splice, the tool emits once more on the spliced draft and splices again — a PRIME step — before the baseline and the comparison. A re-close of an already-filled manifest does not prime, so a genuine drift still fails. The second defect is one line: step 1 replaces the Closing line with the closing file verbatim, so a file without the `**Closing:**` label erases it; step 1 now refuses such a file and leaves the draft untouched.

## Why this exists

A tool whose first run fails by construction teaches its users to run it twice, and a user who runs a tool twice stops reading why the first run failed. Today that habit hid the prefix defect for one close and cost a restore. The tool now closes on its first run, or refuses before it writes.

- Change what `cycle_check` computes, or widen the fixed point to `cycle_check` drifts on a filled manifest (c11 and c13b pin the refusal).
- Prepend a missing label: the tool refuses and says what it expects.
